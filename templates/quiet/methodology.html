Board · Methodology

How the Quiet Board measures and ranks

The board measures what a checker's users live with: how long they wait, on one core and on four, how much memory it takes, how much energy it burns, and whether it ever accepts a false proof. When the measure is the thing itself, optimising for the board is optimising the checker.

Principles

  • Measure the target. Wall time, peak memory and energy on real libraries make up the overall score. Instructions retired, the Arena's own measure, have a category of their own and decide the Arena's order, kept beside the others so the two boards read side by side; cycle counts are recorded for every run and shown.
  • Many orthogonal measures. Specialising in one costs on the others; a checker no one beats on all four at once is marked Pareto-optimal.
  • Breadth with bounded weight. Whole libraries, stress tests and small files each carry a fixed share; within a family every test weighs the same, except Mathlib, which carries half of the libraries' share.
  • Honest uncertainty. Every factor carries a 95% interval and every rank an interval; checkers the data cannot separate share a rank.
  • Runs that prove their conditions. A run that ran at the wrong frequency, was throttled, shared its cores or had a counter multiplexed is kept for the record and repeated; it never reaches a median.
  • Rules fixed in advance. A season's scoring file is committed before its first run; changing it starts a new season.
  • Everything published. Every run record, the machine's configuration and the scoring code are public; the board re-scores to the same bytes.

The machine

One dedicated mini PC that does nothing else. CPU 0 keeps the system, the runner, the measurement helper and every interrupt; the four-core lane is the whole machine, the one-core lane is CPU 3 alone. The clock is pinned to the highest frequency the machine holds on all cores for two hours without throttling, so a second of wall time means the same thing in every run and every week.

One run

A checker runs as its own user, in its own network namespace (loopback only) and mount namespace, with its home behind an overlay whose writes vanish when the run ends, so no run can leave anything for the next and no checker can reach another's build. It gets the same environment block, byte for byte in size, whichever checker and test it is, because the size of the environment moves the initial stack and with it the alignment of everything a program puts there.

Every run must prove the conditions it was measured under, or it is repeated:

|cyclesu+cyclesktask-clock·fpinned−1| ≤0.5%, ∑p∈lanebusyp−CPU(run) ≤max(20 ms,0.5%·wall·|lane|)

no thermal-throttle event during the run, and every hardware counter counted the whole time (never a multiplexed estimate). On hybrid processors perf scales each core type's count by its share of the run; the board undoes that scaling and adds the core types, which is exact.

A verdict is the checker's exit code, as on the Arena (0 accept, 1 reject, 2 decline), with one difference: a run in which any of the checker's processes died of a failure signal or of memory is an error, whatever exit code a wrapper made of it. Process accounting sees every process the checker started.

How many runs

Each checker runs each test on each lane in passes, every pass visiting every unfinished cell once in an order drawn from the round and the pass number, so slow drift of the machine falls on all checkers alike. A cell's statistic is its median, bounded by the interval that holds for any continuous distribution:

[x(k),x(n−k+1)], k=max{j≥1: 2−n∑i<j(ni) ≤1−γ2}

with confidence γ=0.95. A small test runs at least {{ machine.repetitions.scored.n_min if machine.repetitions else 7 }} times and until the interval's half-width is within {{ '%.0f' % ((machine.repetitions.scored.ci_rel if machine.repetitions else 0.01) * 100) }}% of the median; a heavy one (over a minute) three times, more while the spread exceeds 1%. A timeout is final; so is a failure seen twice. A bad proof is run three times, and accepting it once is enough to be unsound.

The score

For each metric m (wall time on four cores, on one core, peak memory, energy, instructions), each family f and each test t, a checker c is compared with the reference r by a log ratio:

S(c)= ∑mαm ∑fβf ∑t∈fwf,t ln⁡ max(xm(c,t),φm) max(xm(r,t),φm) , factor(c)=e−S(c)

so a factor is a weighted geometric mean of how many times better than the reference the checker is. The weights of a category sum to one, as do wf,t within each family. The floors φm ({{ (season.floors.wall_s * 1000) | int }} ms, {{ season.floors.memory_bytes | bytes }}, {{ season.floors.energy_j }} J, {{ season.floors.instructions | instructions }} instructions) are the differences no one using a checker would notice. Because the reference enters every score as the same constant,

Sr′(c)=Sr(c)−Sr(r′)

and the order of the board is the same whichever checker is the reference (Fleming and Wallace, 1986). A good test a checker does not accept, by timeout, error, decline or memory, is scored at twice its cap, as the SAT Competition's PAR-2:

xtime=2Tt, xmemory=2M, xenergy=2P^Tt, xinstructions=2RTt

where Tt is the test's own time limit: a shorter limit a checker sets for itself may end its run sooner, but it never lowers what the failure costs. R, {{ season.caps.instruction_rate | instructions }} instructions a second, is the rate the Arena itself uses to turn instructions into time.

The Arena's order

One category ranks exactly as the official Arena's board does, from this board's runs: lexicographically by

key(c)=( nunsound, nincomplete, IMathlib, ndeclined)

the invalid proofs it accepted, the valid proofs it rejected, its instructions on Mathlib (infinite if it did not check Mathlib, or no count was taken), and the tests it declined, an error or a timeout counting as a decline and a corner case only when declined. Checkers equal on all four keep the order in which the Arena reads them. Unlike every other category it places every checker, the reference and the unsound included. Its places are confidence sets drawn from the same replicates as every other rank. The test suite checks it against the Arena's own code, lka.py's board_order_key, on a published round and on randomly drawn ones, so the two orders cannot drift apart.

Places, uncertainty and ranges

A category's places are a competition's: they follow the estimate on the season's own suite, best first, and never go back. Two neighbours share a place only when the noise of their runs cannot tell them apart. For that, the board is redrawn {{ board.bootstrap.replicates }} times with the suite held fixed, each replicate drawing every cell's median from its exact bootstrap distribution,

P(X(k)*≤x(j))= ∑i=kn (ni) (jn)i (1−jn)n−i, k=⌈n2⌉

and down the order a checker shares the place above it unless the checker above wins in at least 1−α2(N−1) of these replicates, a bound corrected for the N−1 neighbouring comparisons. A place is therefore decided by the suite the season fixed, and only measurement noise can tie it.

Which tests a suite holds is a choice, and a checker tuned to one suite would show it here. So a second set of {{ board.bootstrap.replicates }} replicates also redraws each family's tests with replacement (Mathlib, pinned to half of the libraries, stays), the same draws for every checker. A checker's factor interval is the middle 95% of its replicate factors against the reference's in the same replicates, and the range beside its place is the marginal confidence set for its rank of Mogstad, Romano, Shaikh and Wilhelm (2024): with N ranked checkers and α=1−γ,

rank(c)∈[ 1+#{d:p^dc≥τ} , N−#{d:p^cd≥τ} ], τ=1−α2(N−1)

where p^dc is the share of replicates in which d scores better than c. The bound τ corrects for the N−1 comparisons each checker takes part in, so the set covers the checker's true rank with probability γ. A narrow range is a place the suite's composition cannot argue with; a wide one is a place that rests on which tests were chosen. Both are in board.json, the range's left end as rank.

The Pareto layers need neither weights nor resampling: layer 1 is every ranked checker no other beats on every Pareto category at once, layer 2 is the same once layer 1 is set aside, and so on. Every random draw, of run order and of resampling, comes from one generator, SplitMix64, seeded by name, so the board re-scores to the same bytes on any machine.

Reproduce it

Everything on the board comes from board.json and the run records behind it. To score the records again:

python3 lka.py quiet-score --season scoring/{{ season.season }}.yaml --machine machines/{{ machine.name }}.yaml \
    --manifest staged/manifest.json --results results --epoch {{ board.epoch }}

To check the measurement chain on any Linux machine with Docker: quietbox/selftest-in-container.sh.

Disclosure

The board is run by Tristen Harr, whose checker logos-kernel is one of its entries. It is built from its Arena entry and measured exactly like every other; the rules of each season are committed before its first run, and every run record is published so that anyone can check that.
